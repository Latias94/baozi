# Changelog

All notable Baozi changes should be recorded here.

Baozi makes no stable compatibility promise while its importer foundation is being built. This Unreleased section describes the first canonical portable candidate; it does not announce a registry release.

## Unreleased

- Import STL and OBJ/MTL through the default facade, with PLY and the selected glTF/GLB profile available as explicit features. The glTF profile retains all seven primitive modes, sparse accessors, complete influence sets, scene selection, PBR/unlit materials, skins, morphs and TRS curves within its [documented restrictions](docs/formats/gltf.md).
- Consume one immutable validated Scene through borrowed typed readers for geometry, hierarchy, placements, appearance, deformation, animation, cameras and lights. Generation-qualified IDs reject stale handles; Vertex, Corner and Face domains remain distinct.
- Preserve built-in PLY Position, Normal and Texcoord precision per declared stream, including adjacent F64 values, finite tiny values and signed zero. Dense/sparse F64 geometry continues through reads, edits, generated fields, space conversion and F64 world bounds. Application packing remains an explicit conversion.
- Prepare an explicit primitive selection with one `prepare_triangles` transaction: lower polygons/strips/fans, optionally generate flat/smooth normals and apply one Tangent policy. Work/storage limits and Normal orientation are explicit; later failure or cancellation returns the original Scene. Reports retain every selected target's final ID and Changed/Unchanged disposition with actual origins and field effects.
- Generate Corner tangents from explicit Normal and UV domain keys with the Baozi Triangle UV Derivative v1 algorithm, retaining dependency/replaced-field width and `SignInW` declarations. It does not claim MikkTSpace compatibility. Invalidating Normal/Tangent morph dependencies reject at the common edit boundary.
- Convert complete Scenes using validated basis, unit and winding facts. Geometry, authored Matrix/TRS transforms, skin matrices, morph deltas, curves, camera/light frames and material lengths follow the same conversion; unknown source facts require explicit assumptions. Unchanged image/text payloads remain shared.
- Read application list tuples without allocation through `list_vertices` and strict `triangle_vertices`. Exact strip/fan assembly, source Vertex/Corner/Face identity, sparse values, influences and morph deltas remain available while applications choose their own buffers and indexing policy.
- Distinguish `MaterialAssignment::{Unspecified, Authored, ImplicitDefault}` through public primitive reads and authoring. The glTF adapter creates one shared generated default PBR material only when selected primitives need it, preserving authored absence and source counts. Use `authored_material()` or `effective_material()` instead of the former ambiguous material accessor.
- Retain complete material factors and binding interpretation, channel swizzles, strengths, blend operations, transforms and UV-set indices. Image, Texture and Sampler names belong to their own source objects; encoded bytes and declared media type remain available without pixel decoding.
- Build a bounded owned `SceneRelations` index for parent and node-to-instance navigation. Construction has explicit work/storage limits; lookups allocate nothing and retain their generation after Scene teardown.
- Preserve source-object metadata independently from canonical owners, including exact selected glTF extras bytes. Borrowed metadata, source/resource and owner-to-provenance readers expose retained ancestry without rebuilding the graph; edits retain unrelated source attachments and payloads.
- Decode glTF through a private metered selected-profile document borrowing immutable JSON/BIN input. Typed tables, decoded strings and validation scratch are admitted by their actual owners. Removed the opaque allocation multiplier and both maintained glTF forks; the portable production closure now contains ten packages.
- Keep import and postprocess limits, cooperative control, diagnostics, optional-dependency outcomes and authorized source-semantic loss explicit. Dependency-cache and resource-graph work is metered. Reader cleanup faults remain attributed to host IO, preserve the first terminal cause and leave healthy format registrations usable.
- Resolve final MTL opacity from the final authored value, bound PLY metadata ordering work, and preserve glTF endpoint-clamping semantics for retained animation. Canonical validation rejects orphaned Normal/Tangent morph deltas.
- Use facade-exported format options and bounded byte/memory/sidecar examples, including an application-owned host-file snapshot recipe. The [independent asset consumer](tools/consumers/assets/README.md) retains complete static UV/material/sampling output and demonstrates CPU curve, morph and skin evaluation after Scene teardown.
- Require Rust 1.95 and the standard library. The complete public facade feature union remains portable; `default-features = false` selects no built-in format. Execution and compilation evidence retain their exact source, toolchain, target and profile in the [maturation review](docs/reviews/2026-11-02-first-release-maturation.md).
- Rehearse unchanged ten-package Cargo archives with version-only consumer roots and a standard offline directory source, without root patches or checkout substitutions. Package-local README/license files and optional production edges are checked. Archive success establishes local distribution behavior; public registry availability remains a separate release step.
- Keep native filesystem and repository-capture experiments in the excluded, unpublished `baozi-native-io-candidate`. Maintained `baozi-cap-primitives`, `baozi-cap-std` and `baozi-cap-fs-ext` 0.1.0 packages use normal dependency edges, preserve upstream authorship/licenses and bound native link traversal. No native target has release-registered support.
- Replace superseded production reconstruction paths and bootstrap record encodings with the shared typed Scene and operation owners. Semantic snapshot encoding is revision 7; snapshots remain bounded diagnostic evidence, not a compatibility or persistence format. Direct `generate_normals` now receives its explicit `TangentPolicy` argument.

The existing registry `baozi 0.0.1` is a placeholder. Publication of a verified replacement and any subsequent yank are separate operations under the [release policy](docs/contributing/release-policy.md).
