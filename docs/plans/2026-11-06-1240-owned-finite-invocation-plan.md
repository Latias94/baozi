## Concrete state and interfaces

The next concrete compiler cut separates finalizable envelopes from their private
borrowed algorithms. An operation/assembly envelope holds its loan by value during
ordinary execution; consumers borrow that stored loan through explicit accessors.
Move algorithm bodies once, rather than adding a forwarding method for each ordinary
operation. Publication open and validation preserve their original recovery owner,
proof, fallback cause and containment flag. Only the assembly loan has the existing
abandonment destructor; the concrete envelope adds no second cleanup duty.

Concrete finalizers recover the original typed fields before lending the shorter
classification/qualification/Ready scope. Shared methods stop at ownerless decisions;
prepared outputs, exact joint intents and failure residue remain concrete. Establish
this boundary with live dynamic callers first. Keep backend selection concrete until
its real finite physical qualification and consuming leaf are available; do not add an
unsupported finite branch or claim unused selectors as integration. When selected
loans are introduced, checked recovery precedes all owner takes. Crate-private mutable
loan access is an internal backend-preservation invariant, not a static type proof:
audit callers against whole-loan replacement and use shorter concrete-root views if
